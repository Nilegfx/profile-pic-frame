## Visuals

**Focal Point:**
The 500×500 canvas container is the primary visual anchor at all times — it dominates the screen both when empty and when a photo is loaded. The control row (upload button, download split-button, frame picker) is secondary and lives below the canvas. The user's attention flows: canvas → control row → frame picker.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Upload Photo |
| Download CTA | Download (1×) / Download (2×) |
| Empty state (before photo) | [No visible empty state text — user sees blank canvas with controls] |
| Aria label (photo node) | `aria-label="User photo — drag to reposition, use corner handles to resize"` |
| Aria label (transformer) | Not applicable — Konva Transformer has no native ARIA support; interaction is visual-only |

**Changes from Phase 4:**
- **Removed:** "Photo Size" label (was above photo-scale slider — slider and label removed per D-08)
- **Added:** Cursor feedback for drag interaction — `cursor: grab` on hover, `cursor: grabbing` while dragging (user decision)

**Accessibility note:** Konva canvas layers are not accessible to screen readers. This is a known limitation of canvas-based editing tools. ARIA labels on HTML controls remain intact (Upload button, Download button, resolution dropdown).

## Interaction Contract

### Transformer — Visual Specification

| Property | Value | Rationale |
|----------|-------|-----------|
| Enabled anchors | `['top-left', 'top-right', 'bottom-left', 'bottom-right']` | Corner anchors only (D-01) — no edge anchors, cleaner UI |
| Keep ratio | `true` | Aspect ratio locked at all times (D-02) — no distortion |
| Anchor size | `10px` | Claude's discretion — 10px provides good touch target without visual clutter |
| Anchor fill | `#FF6B35` | Orange accent (D-03) |
| Anchor stroke | `#FFFFFF` | White border for contrast (D-03) |
| Anchor stroke width | `2px` | Claude's discretion — 2px visible against orange fill |
| Border stroke | `#FF6B35` | Orange accent (D-03) |
| Border stroke width | `2px` | Claude's discretion — matches anchor stroke width for consistency |
| Visibility | Always-on when photo loaded (D-04) | Single-select model — only one image on canvas |
| Layer | Dedicated `transformerLayer` (D-05) | Third layer above `frameLayer` for clean hide/show |

### Drag — Interaction Specification

| Property | Value | Rationale |
|----------|-------|-----------|
| Draggable | `true` on photo node (D-06) | User can reposition photo freely |
| Cursor on hover | `cursor: grab` | User decision — indicates draggable element |
| Cursor while dragging | `cursor: grabbing` | User decision — indicates active drag |
| Visual feedback | None — clean drag, no shadow or outline | User decision — minimal visual clutter |
| Drag bounds | Constrained via `dragBoundFunc` (D-07) | Photo cannot be dragged entirely off 500×500 stage |
| Drag clamping math | Keep image center within stage bounds | Claude's discretion — simplest approach that prevents full off-canvas |

### Export — Handle Hiding Pattern (D-12)

Before calling `stage.toDataURL()`:
```javascript
transformer.hide();
transformerLayer.batchDraw();
```

After `toDataURL()` completes (synchronous):
```javascript
transformer.show();
transformerLayer.batchDraw();
```

**Rationale:** Transformer handles must be invisible in downloaded PNG. Hide/show pattern is cleaner than detach/reattach.
