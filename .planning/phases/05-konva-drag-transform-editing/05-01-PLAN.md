```javascript
// D-07: Constrain drag so at least 50px of image remains visible
imageNode.dragBoundFunc(function(pos) {
  const scaledWidth = this.width() * this.scaleX();
  const scaledHeight = this.height() * this.scaleY();
  const minVisible = 50; // At least 50px must remain visible
  
  const maxX = stage.width() - minVisible;
  const minX = minVisible - scaledWidth;
  const maxY = stage.height() - minVisible;
  const minY = minVisible - scaledHeight;
  
  return {
    x: Math.max(minX, Math.min(pos.x, maxX)),
    y: Math.max(minY, Math.min(pos.y, maxY))
  };
});
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → File System | User uploads image file from local disk — untrusted content enters the browser's image decoder |
| Canvas → Export | User triggers PNG download — composited canvas data crosses into file system as downloaded file |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | Malicious image file upload (exploit image decoder via crafted PNG/JPEG) | accept | Browser's native image decoder handles untrusted files. MIME validation (`image/jpeg`, `image/png`) rejects non-image files. No server-side processing = no server-side vulnerability. Modern browsers (Chrome 90+, Firefox 88+, Safari 14.1+) have hardened image decoders. Risk: low. |
| T-05-02 | Information Disclosure | CORS tainting (tainted canvas prevents toDataURL) | mitigate | All images loaded from same origin: user photo via FileReader (data URI), frames from local PNGs. No cross-origin requests = no taint risk. `toDataURL()` succeeds unconditionally. |
| T-05-03 | Denial of Service | Drag photo entirely off-canvas, making it unrecoverable | mitigate | `dragBoundFunc` clamps position so at least 50px of image remains visible within 500×500 stage (Task 2). User can always click and drag photo back. No refresh required. |
| T-05-04 | Information Disclosure | Transformer handles visible in downloaded PNG (leaks UI state) | mitigate | Explicit hide/show pattern: `transformer.hide()` + `transformerLayer.hide()` before `toDataURL()`, `transformer.show()` + `transformerLayer.show()` after (Task 3, D-12). Verified in acceptance criteria. |
| T-05-05 | Denial of Service | Large image (100MB+) causes browser hang during Konva transform | accept | Client-side performance issue. Modern browsers handle large images via tiling and GPU acceleration. Konva's transform is GPU-accelerated (canvas 2D API). If user uploads extreme image (e.g., 50,000×50,000px), browser may hang — this is expected client-side behavior, not a security vulnerability. No server to protect. |

**Notes:**
- **No new network requests** in Phase 5. All operations are local canvas transformations (drag, scale). No API calls, no data exfiltration.
- **No XSS risk** from transformer styling. Transformer config properties (`anchorFill`, `borderStroke`) accept CSS color strings, not arbitrary HTML. Konva renders these as canvas primitives (fillRect, strokeRect), not DOM injection.
- **No authentication/authorization** concerns — this is a client-only, single-session tool with no user accounts or protected resources.

</threat_model>
