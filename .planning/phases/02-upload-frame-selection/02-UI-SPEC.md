## Component State Specifications

### Photo Upload Flow States

**BEFORE upload (empty state):**
- Canvas displays gray background rect (#F5F5F5, 500×500px)
- Placeholder text visible: "Upload a photo to get started" (#9CA3AF, 14px, centered)
- Upload button enabled (#FF6B35 background)
- Frame thumbnails visible but no visual indication of selection state
- Scale sliders present but non-functional (photo/frame nodes don't exist yet)
- Download button enabled but will produce empty canvas export (Phase 4 behavior)

**DURING upload (loading state):**
- No loading indicator required (local files via FileReader load instantly)
- Canvas remains in empty state until photo is fully loaded
- Upload button remains enabled (user can re-upload immediately)

**AFTER upload (photo loaded state):**
- Empty state elements disappear: `background` rect and `placeholderText` hidden or removed
- User's photo visible as Konva.Image on photoLayer
- Photo centered on canvas at natural pixel size (offset point: x:250, y:250)
- Photo scale: 1.0 initially (no scaling applied on upload)
- Upload button remains enabled (allows replacement upload per D-08)
- Scale sliders functional (photo slider controls photoImage node)
- Download button remains enabled

### Frame Selection Flow States

**BEFORE selection:**
- Frame thumbnails rendered dynamically by `discoverFrames()`
- All thumbnails have default border: 2px solid #E5E7EB
- No frame visible on frameLayer (canvas shows photo only)
- Frame scale slider present but non-functional (no frameImage node yet)

**DURING selection (loading state):**
- No loading indicator required (local PNG files load instantly via Konva.Image.fromURL)
- Selected thumbnail border remains in transition state (browser default CSS transition: 0.2s ease)

**AFTER selection (frame loaded state):**
- Selected thumbnail border changes to 2px solid #FF6B35
- Previous selected thumbnail (if any) returns to 2px solid #E5E7EB
- Frame PNG visible as Konva.Image on frameLayer (renders above photo)
- Frame sized 500×500px, placed at x:0, y:0 (full canvas overlay)
- Frame scale: 1.0 initially
- Frame scale slider becomes functional (controls frameImage node)
- `state.selectedFrame` updated to frame ID (e.g., 'frame-1')
- `state.frameImage` updated to new Konva.Image node

### Replacement Behavior

**Second photo upload (D-08):**
- Previous photoImage node removed from photoLayer before new one added
- Canvas never shows both old and new photo simultaneously
- Empty state does NOT reappear (photo replaces photo, not empty → photo)
- Frame selection persists (frameImage node remains on frameLayer per D-09)
- Photo scale resets to 1.0 (new photo starts at natural size)

**Second frame selection (D-04):**
- Previous frameImage node removed from frameLayer before new one added
- Canvas never shows both old and new frame simultaneously
- Frame scale resets to 1.0 (new frame starts at natural size)
- Photo selection persists (photoImage node remains on photoLayer)

### Error Handling States

**File validation (D-06, D-07):**
- OS-level filtering via `accept="image/png, image/jpeg"` prevents unsupported file types at picker level
- Files bypassing the filter (e.g., drag-drop bypass) are **silently ignored**
- No error message displayed
- No console warning required
- Canvas state unchanged (existing photo remains or empty state persists)
- Upload button remains enabled (user can try again)

**No error state visuals:**
- No error text copy
- No error color (#DC2626 or similar) used
- No shake animation or visual rejection feedback
- Validation handled invisibly per user decision

## Interaction Contract

### Upload Flow (Phase 2 implementation)

1. User clicks "Upload Photo" button
2. Browser file picker opens (accept: "image/png, image/jpeg")
3. User selects a JPEG or PNG file
4. FileReader reads file as Data URL
5. Konva.Image.fromURL creates image node from Data URL
6. Photo placed at natural pixel size, centered (offset: x:250, y:250)
7. Empty state elements hidden: `background.visible(false)`, `placeholderText.visible(false)`
8. photoImage node added to photoLayer
9. `state.photoImage` updated to new Konva.Image reference
10. photoLayer.draw() called to render changes

**Timing:** Instant for local files (no loading spinner needed)

**Repeat upload:** Step 6 removes previous photoImage node before adding new one

### Frame Selection Flow (Phase 2 implementation)

1. User clicks one of the dynamically generated frame thumbnails
2. JavaScript click handler (extended from Phase 1 discoverFrames()) executes
3. All `.frame-thumbnail` elements have `.active` class removed
4. Clicked thumbnail gets `.active` class added (border becomes #FF6B35)
5. Konva.Image.fromURL loads frame PNG from local file (e.g., 'frame-1.png')
6. If previous frame exists, remove old frameImage node from frameLayer
7. New frameImage node created with width:500, height:500, x:0, y:0
8. frameImage node added to frameLayer
9. `state.frameImage` updated to new Konva.Image reference
10. `state.selectedFrame` updated to frame ID (e.g., 'frame-1')
11. frameLayer.draw() called to render changes

**Timing:** Instant for local PNG files (no loading spinner needed)

**Repeat selection:** Step 6 removes previous frame before adding new one

### Error Handling Flow (silent ignore)

**Unsupported file bypasses OS picker:**
1. FileReader reads the file
2. JavaScript validates MIME type or file extension
3. If invalid: no action taken, function returns early
4. Canvas state unchanged
5. No user feedback provided

**No error message contract:** Phase 2 does not implement error messages. Per D-07, invalid files are silently ignored.
