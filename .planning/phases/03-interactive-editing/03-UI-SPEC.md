## Interaction Contract

### Photo Size Slider Behavior

**Trigger:** `input` event on `#photo-scale` range input (min="0.5" max="2" step="0.1" value="1").

**Action:**
1. Read slider value (0.5 to 2.0)
2. Update `state.photoScale` to match
3. Update `state.photoImage` node:
   - Set `scaleX` = `scaleY` = slider value (uniform scale, aspect ratio locked)
   - Recalculate `offset({ x: naturalWidth * scale / 2, y: naturalHeight * scale / 2 })` to keep image centered
   - Position stays at `{ x: 250, y: 250 }` (stage center)
4. Call `photoLayer.batchDraw()` for real-time preview

**Source:** 03-CONTEXT.md D-03, D-04, D-05, D-06, D-09, D-10.

**Centering formula (locked from Phase 2):**
```javascript
position({ x: 250, y: 250 })
offset({ x: naturalWidth * scale / 2, y: naturalHeight * scale / 2 })
```

### Slider Reset on Upload

**Trigger:** New photo upload (FileReader `onload` in photo upload handler).

**Action:**
1. Reset DOM slider: `document.getElementById('photo-scale').value = 1`
2. Reset state: `state.photoScale = 1`
3. New photo node is centered at default scale (1.0) using the same centering formula

**Source:** 03-CONTEXT.md D-08.

### Frame Size Slider (Hidden)

**Action:** Hide the Frame Size control group (`<div class="control-group">` wrapping `#frame-scale`, lines 198-201 in `index.html`).

**Method (Claude's discretion):** Apply `style="display:none"` inline OR add a CSS class `.hidden { display: none; }` and apply it to the control group.

**Source:** 03-CONTEXT.md D-01, D-02 — frame is fixed at 500×500, user cannot scale it.

### Canvas Preview (No Changes)

- Canvas container is 500×500 (existing CSS line 156-162)
- Photo renders on `photoLayer`, frame renders on `frameLayer` (existing Konva setup)
- No style changes needed for canvas area in Phase 3
