```javascript
// 1. App state object (module scope)
const state = {
  photoImage: null,
  frameImage: null,
  photoScale: 1,
  frameScale: 1,
  selectedFrame: null
};

// 2. Konva Stage initialization
const stage = new Konva.Stage({
  container: 'stage-container',
  width: 500,
  height: 500,
});

// 3. Two layers (per D-14: photo below, frame above)
const photoLayer = new Konva.Layer();
const frameLayer = new Konva.Layer();
stage.add(photoLayer);  // Add photo layer first (renders below)
stage.add(frameLayer);  // Add frame layer second (renders above)

// 4. Empty state placeholder (per D-11: gray fill + centered text)
const background = new Konva.Rect({
  x: 0,
  y: 0,
  width: 500,
  height: 500,
  fill: '#F5F5F5',  // Light gray from UI-SPEC.md
});
photoLayer.add(background);

const placeholderText = new Konva.Text({

  align: 'center',

  y: 242,  // Vertically centered (500/2 - 14/2 ≈ 242)
});
photoLayer.add(placeholderText);
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local filesystem → Browser | konva.min.js and index.html loaded from filesystem into browser sandbox |
| User's browser → No external network | No runtime network requests (Konva loaded locally) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | konva.min.js | accept | File served from local filesystem; if attacker has local file access, system is already compromised. Integrity check via file size (181.5 KB) in acceptance criteria provides basic verification. |
| T-01-02 | Information Disclosure | index.html source code | accept | All code is client-side JavaScript and intentionally visible (view-source). No secrets, API keys, or PII embedded in Phase 1. This is expected and acceptable for a campaign tool. |
| T-01-03 | Denial of Service | Konva Stage initialization | accept | Konva 10.2.5 is stable library; no user input processed in Phase 1. If browser crashes on Stage init (extremely unlikely), user refreshes page. No mitigation needed — low risk. |
| T-01-04 | Elevation of Privilege | JavaScript execution in browser | accept | JavaScript runs in browser sandbox with no privileged operations. No server-side code, no system calls, no file system access beyond what browser allows (standard web security model). |

**Phase 1 Security Posture**: Minimal attack surface. No user input, no network requests, no sensitive data, no authentication. All threats accepted as low risk. Phase 2+ will introduce file upload and image processing (reassess then).
</threat_model>
